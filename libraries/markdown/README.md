# markdown

[CommonMark](https://spec.commonmark.org/0.31.2/) 0.31.2 to HTML for kpp, with GitHub's tables
and heading ids as options. Its output is the spec's, byte for byte: all 655 examples of the
CommonMark spec pass, as do the 8 table examples of the GFM spec ([Conformance](#conformance)).

```cpp
String html = markdownToHtml("# kpp\n\nFast *builds*.\n");  // <h1>kpp</h1>\n<p>Fast <em>builds</em>.</p>\n

MarkdownOptions options;
options.tables = true;      // | a | b |
options.headingIds = true;  // <h2 id="hosting-on-kppnet">
String page = markdownToHtml(readme, options);
```

## What it supports

**All of CommonMark 0.31.2**, nothing left out: the subset this library was asked to define turned
out to be the whole spec (conformance/run.cmd checks every example).
- Blocks: paragraphs, ATX and setext headings, thematic breaks, indented and fenced code blocks
  (the info string's first word as `class="language-..."`), HTML blocks (all seven kinds), link
  reference definitions, block quotes, bullet and ordered lists, tight and loose, with lazy
  continuation lines and tabs as the spec counts them.
- Inlines: code spans, emphasis and strong emphasis by the spec's delimiter run rules, inline,
  reference, collapsed and shortcut links and images, autolinks (URI and email), raw HTML, HTML5
  named and numeric character references, backslash escapes, hard and soft line breaks.
- Unicode where the spec asks for it: punctuation and whitespace for emphasis (Unicode's P, S and
  Zs categories), and case folding for link labels (`[ẞ]` matches `[SS]`), from tables generated
  from Python's `unicodedata` (Unicode 16.0).

**Options** (`MarkdownOptions`, all off by default, so the default is plain CommonMark):
- `tables`: GitHub's tables (GFM spec 0.29, "Tables (extension)"): a header row, a delimiter row
  with `:` for alignment (`align="left|center|right"`), body rows; `\|` in a cell. A table
  interrupts a paragraph, and ends at a blank line or at a line that starts another block.
- `headingIds`: `id` on every heading, as GitHub makes it, so that links to `#a-heading` work:
  the heading's text lowercased, spaces as `-`, letters, digits, `-` and `_` kept and the rest
  dropped; a repeated id gets `-1`, `-2`...

**Not done**, on purpose: raw HTML passes through unchanged (CommonMark's rule), so the input
must be trusted, as this repository's own documents are. There is no "safe" mode yet.

## API

| | |
|---|---|
| `String markdownToHtml(StringView text, const MarkdownOptions& = {})` | the document's HTML |
| `MarkdownOptions` | `tables`, `headingIds`, and `rewriteLink`: a `Function<String(const String&)>` called with every link's and image's destination (percent-encoded), whose result is written instead; a site turns `.md` links into `.html` with it |

Text is UTF-8; line ends are `\n`, `\r\n` or `\r`; a zero byte becomes U+FFFD, as the spec says.
`markdownToHtml` throws nothing: every text is a CommonMark document.

## How it is built

A port of the spec's reference parser, commonmark.js (its `blocks.js`, `inlines.js` and HTML
renderer), to kpp:
- `MarkdownNode.kpp`: one node type for blocks and inlines, linked as commonmark.js links them,
  in a Deque the document owns;
- `MarkdownBlocks.kpp`: the line-by-line block parser, HTML block and raw HTML matching
  (hand-written where commonmark.js uses regular expressions), tables;
- `MarkdownInlines.kpp`: the inline parser with the delimiter and bracket stacks;
- `Markdown.kpp`: `markdownToHtml` and the renderer;
- `MarkdownEntities.kpp` and `MarkdownUnicode.kpp`: tables generated by `generate_entities.py`
  (the WHATWG named character references, from Python's `html.entities`) and
  `generate_unicode.py`.

Speed: the 54 Markdown files of this repository (1.3 MB) in 0.056 s with `--release`, tables and
heading ids on (one run on PC-PRACOVNA).

## Tests

`kpp --test` in this directory, or `kpp --test libraries/markdown` anywhere: the library's own

## Conformance

`libraries/markdown/conformance/run.cmd` checks the library against every example of the
CommonMark spec 0.31.2 (655) and every table example of the GFM spec 0.29 (8), byte for byte, and
the CommonMark examples again with tables on. All pass. The specs are under
[CC-BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/), a share-alike license that the
repository's (Apache-2.0 WITH LLVM-exception) does not take in, so the examples are not kept here:
run.cmd fetches [commonmark-spec](https://github.com/commonmark/commonmark-spec) and
[cmark-gfm](https://github.com/github/cmark-gfm) at fixed commits into
`%TEMP%\kpp-conformance\markdown`, `generate_spec.py` turns their examples into kpp data there,
and `kpp --test` runs `CommonMarkTests.kpp.in` on them. It needs git, Python and the network the
first time.

## Generated tables

`src/MarkdownEntities.kpp` (by `generate_entities.py`, from Python's `html.entities.html5`, which
is the WHATWG HTML standard's list of named character references) and `src/MarkdownUnicode.kpp`
(by `generate_unicode.py`, from Python's `unicodedata`) are facts about HTML and Unicode in kpp's
form: the names and the characters they stand for, and which code points are punctuation and how
they case-fold.
